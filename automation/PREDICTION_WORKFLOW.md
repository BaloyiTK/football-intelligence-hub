# Daily Prediction Workflow

ChatGPT is the research/orchestration layer. GitHub stores the auditable inputs, checkpoints and frozen outputs; repository automation validates/publishes evidence already written to the repository and must never invent missing research.
## Execution preflight
Before step 1, apply the mandatory preflight/self-correction contract in `AGENT_INSTRUCTIONS.md`. Do not begin discovery from remembered rules. If an execution path fails, repair and continue through the next approved path rather than converting a recoverable mistake into a run blocker.


1. Resolve the requested daily run date/time in Africa/Johannesburg.\n3. Before today's discovery, reconcile recent prediction archives that still contain unverified/pending results. Search public web for final results, identity-match by date/competition/home/away, require authoritative or independently corroborated final-score evidence where practical, grade only verified final scores with `lib/grading.ts`, and update only the separate `result` object plus daily `results` aggregate. Never alter frozen prediction/model/recommendedBet fields. If a result remains unresolved, preserve it as pending with attempted verification sources/timestamp and continue other fixtures.
2. Read the complete mandatory rule chain from `automation/AGENT_INSTRUCTIONS.md`. Before creating a run, inspect today's persisted runs and resume the latest non-complete resumable run from its exact cursor/resumeAction; otherwise create a new run. Freeze the current `data/leagues.json` registry snapshot for a new run.\n4. Discover the requested date's worldwide senior-football fixture universe using at least TWO independent global date-indexed sources, following `FIXTURE_DISCOVERY.md`.\n5. Normalize/map fixtures to every competition in the frozen registry. Persist discovery sources, mapped fixtures, verified zero-fixture checkpoints, and legitimate out-of-registry senior competition coverage-gap candidates before modelling.\n6. Process every configured competition through the FINAL entry. Resolve discovery disagreements/ambiguities with targeted verification rather than skipping them.\n7. Before researching each fixture, verify it is still pre-match. Exclude/invalidate started, live, completed, cancelled or abandoned fixtures from new predictions.\n8. Research each verified upcoming fixture under `RESEARCH_RULES.md`; attempt Full -> Standard -> Basic -> No Model and preserve evidence sources/cutoff, sampleSize, modelLevel, scoring consistency and recent goal volatility where available. Never fabricate missing inputs.\n9. Run the exact production V2.3 model from `lib/model.ts`. Calculate only the 1X2 probabilities (Home / Draw / Away) and the deterministic reliability-adjusted selector.\n10. Freeze one `recommendedBet` or NO BET/NO MODEL immediately with its evidence/model state. Follow `DUPLICATE_RULES.md`; never append the same fixture twice.\n11. Continue through the final configured competition. A failed/ambiguous search must exhaust alternate global, targeted, official and reputable-statistics fallbacks plus the Full -> Standard -> Basic hierarchy before blocking. Persist fixture-local blockers and continue other independent fixtures; stop globally only when a genuine dependency prevents further safe progress. Re-check kickoff/status immediately before publication.\n12. Validate the run with `npm run run:validate -- <run-file>`. A run may be called complete/final only after `npm run run:finalize -- <run-file>` succeeds.\n13. Build `data/predictions/YYYY-MM-DD.json` under `OUTPUT_SCHEMA.md`. The public betting list contains only still-valid pre-match fixtures with non-null `recommendedBet`; create the dated artifact even when that list is empty.\n14. Run `npm run predictions:verify -- YYYY-MM-DD`, re-read the artifact, and confirm its recommendation count equals the frozen publishable BET count.\n15. After result reconciliation, run `npm run model:train` when new verified graded outcomes exist; persist the candidate and append-only training log with the run/publication artifacts. Consolidate these validated daily artifacts into one final publication commit where practical instead of a chain of intermediate production-triggering commits. GitHub/Vercel automation may deploy/verify repository state, but it does not replace ChatGPT research.\n16. Verify Vercel reports success for the exact final publication commit SHA and that the production site serves the dated archive before describing website delivery as complete. If Vercel is rate-limited or the exact SHA is not deployed, record website delivery as deferred/blocked while keeping the validated GitHub publication intact.\n17. Report recommendations and measured persisted coverage. Before strict finalization, label eligible surfaced bets `PARTIAL — verified/frozen so far`; after finalization and publication verification, they may be labelled final.

`recommendedBet` may contain only a 1X2 selection: Home, Draw or Away. NO BET and NO MODEL are internal audit decisions and are not public recommendations.
